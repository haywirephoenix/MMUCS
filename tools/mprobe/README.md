# mprobe

mprobe runs MMUCS.Core and MMUCS.Runtime from the command line, without the app. It exports the game the way **File ▸ Export** does, draws the debug pictures used to check the room viewer (a room's z-planes, and a room with its actors placed and cut by their z-planes), and runs the game's scripts headless to show what the interpreter does.

## Requirements

- The .NET 8 SDK, as for MMUCS itself.
- The game's resource files. Point mprobe at the first one (`COMI.LA0`); the others beside it are loaded too.

```bash
dotnet run --project tools/mprobe -c Release -- --game D:/Games/COMI/COMI.LA0 COMMAND ...
```

Or set the `MMUCS_GAME` variable once and leave `--game` out:

```bash
export MMUCS_GAME=D:/Games/COMI/COMI.LA0      # PowerShell: $env:MMUCS_GAME = "D:/Games/COMI/COMI.LA0"
dotnet run --project tools/mprobe -c Release -- masked 14 out
```

mprobe also keeps the last game given either way (`mprobe-game.txt` in the app data folder), so after one run with `--game` or `MMUCS_GAME` both can be left out.

## Commands

| Command | What it does |
|---|---|
| `export OUT` | Exports into `OUT` like File ▸ Export. With no option it writes the scripts and the room data, which is what [mscripts](../mscripts/README.md) and [mroom](../mroom/README.md) read. `--scripts`, `--data` and `--images` (backgrounds, object frames, costume cels) pick what to write; `--offsets` keeps byte offsets in the scripts' margin |
| `zplanes ROOM OUT` | Writes the room's background once per z-plane with that plane tinted (`room15_plane1.png` …): plane 1 red, 2 green, 3 blue, 4 yellow, 5 magenta, 6 cyan. Prints how much of the room each plane covers |
| `masked ROOM OUT` | Writes the room as MMUCS.Player draws it, which is how the room viewer and the game draw it too (`room14_masked.png`): the background, the objects in their states on entry, then each actor MMUCS places, at its position, elevation and scale, in SCUMM's draw order, cut by its z-plane. The planes include the objects shown on entry. Lists each actor's costume, position, scale, z-plane and the object it belongs to. `--debug` paints the cut pixels magenta instead (`room14_debug.png`). `--start` draws only what's there as the room opens, as the room viewer starts it: costumes placed on entry, not the player's, one per actor (`room14_start.png`). Each actor's line says when it's placed: `entry`, `entry-if`, `cutscene` or `later`; `--only 122,112` draws just those costumes. `masked all OUT` draws every room (`room013_plndrmap.png` …) with all its costumes and writes the listings to `OUT/costumes.txt`, each actor's line ending with `[box B scale S]`: the walkbox at its feet and the scale it gives, marked `≠` when the actor is drawn at another scale (most of those ignore the boxes on purpose) |

| `audio OUT [music\|voice] [--check]` | Decodes the Digital iMUSE bundles (`.bun` beside the game or in its `resource` folder) into `OUT/music/NNNN.wav` (by the number the track's file name starts with) and `OUT/voice/CODE.wav` (by the line's code), each with a `.meta.json`: format, the track's title, regions, jumps (loops, with hook and crossfade), markers, lip-sync data and the stop point, all in sample frames. Sounds on both discs are written once; musdisk's PRELOAD is skipped. `--check` decodes everything without writing. Prints per bundle the decoder checks: the most bytes a block's bit reader wanted past its data (0 or 1 is right), sounds whose map points outside their data, and per-disc copies that differ (all should be 0). `export OUT --audio` writes the same as part of an export |
| `play ID OUT.wav [--seconds N] [--rate HZ] [--hook HOOK@SECONDS …]` | Plays one bundle sound (`music/1098`, `voice/bccb301`) offline through MMUCS's mixer and iMUSE player (`MMUCS.Core.Media`) into a 16-bit stereo WAV, listing each event as it happens: regions, markers, jumps taken or skipped, and the stop. Loops repeat and jumps crossfade as in the game. `--hook` sets the track's hook at a time: a jump with hook N is taken only when the hook is N, and 128 makes a hook-0 loop fall through once. At `--rate 22050` (the game's rate) the output is the original samples unchanged, apart from crossfades; the default is 44100 Hz, at most 600 s |
| `listen ID [--seconds N] [--rate HZ] [--hook HOOK@SECONDS …] [--device NAME]` | As `play`, but out loud through OpenAL Soft (`MMUCS.Media.OpenAL`, the default sound device unless `--device` names one). Events print when they're mixed, about one latency (93 ms) before they're heard; hooks are set by the played clock, and those at 0 before playback starts, since starting fills the device queue. Prints the latency, underruns (should be 0) and how far the played clock drifted from the wall clock. To check the output without speakers, point OpenAL Soft at its wave writer: an `alsoft.ini` with `drivers=wave` under `[general]` and `file=out.wav` under `[wave]`, then run with `ALSOFT_CONF=alsoft.ini` |
| `cutscene-audio [OUT]` | Decodes every cutscene's sound (its IACT chunks) and checks it: chunks, packets, escaped samples, bytes left over at the end (should be 0), and the sound's length against the picture's. With OUT, writes each as `OUT/NAME.wav` (16-bit stereo, 22,050 Hz) |
| `cutscenes OUT [NAME…]` | Decodes the SMUSH cutscenes (`.san` beside the game or in its `resource` folder) into `OUT/video/NAME/`: one 8-bit indexed PNG per distinct picture under `frame/` (a held shot or an unchanged frame gets no file), and `video.json` with the size, frame rate, sample rate and, under `frames`, the frame whose picture each frame shows. The sound goes to `audio.wav` beside it (16-bit stereo, 22,050 Hz, starting with frame 0). NAME picks videos (`opening`, `finale` …). Prints per video: images written, problems, and two decoder checks: block-coded frames that left data unread (should be 0) and motion copies that reached outside the screen (should be 0). `export OUT --cutscenes` writes the same as part of an export |
| `box ROOM X Y` | Lists the walkboxes at a point (those holding it, or within 80 pixels) with their mask, flags and scale (the box's own, or its scale slot and the scale that gives at the point), the room's scale slots, and the box the engine puts an actor there in, as ScummVM's `adjustXYToBeInBox` does: searched from the last box down to box 1, invisible boxes skipped, and a point outside every box moved to the closest edge. `--player` for the player's actor (player-only boxes). Use it to see why a costume gets the z-plane it does. Then the ways out of that box by the room's box matrix (BOXM): for each other box, `direct`, `via N` (the next box on the way) or `none` |
| `fonts [N] [--char C …]` | The game's NUT fonts as MMUCS reads them (charset N is `fontN.nut`, beside the game or in its `resource` folder): glyph count, line height, capital height and baseline, the ink value and the dark-edge value, whether that edge is an outline all round and whether it's a drop shadow down-right (what a replacement typeface draws), and every pixel value with its count. In room text value 1 takes the text's colour and the others are palette indices. `--char C` (a character or its code, repeatable) draws the glyph: `#` ink, `o` the edge, `.` transparent, other values by number |
| `costume N [ANIM …] [--dir D]` | A costume's chores as the engine reads them (AKCH): where it's exported, the shadow tables its cels draw with (and how many pixels), how many chores, its directions, and each animation's chore per direction with its limbs: `clear`, `stop`, `resume`, or a code and the AKSQ range it starts (`+0`: no length, it runs to the sequence's end op). With ANIM, each limb's AKSQ steps follow, one per line by position: a draw step's cels with their place and size relative to the actor and their bounds, or a control op with its bytes (`C030` jumps, `C0FF` ends). `--dir D` (a number or `N`, `SE`, `W` …) shows one direction |
| `mods [--check] [--place [CEL,…]]` | The mods beside the game and what each replaces: its music tracks, object images and costume cels, hi-res backgrounds and object images (by room, with any that name no room or object), with problems reading them (see [Mods](#mods)). `--place` works out costume cel offsets and saves them to `meta.json`; `--place CEL,…` does just those cels. `--check` decodes every FLAC in the mods with MMUCS's decoder and checks it against the MD5 in its STREAMINFO |
| `backgrounds DIR [--scale N] [--out MOD]` | Which room each image in `DIR` shows, for a mod made of repainted or upscaled backgrounds that don't come named by room. Each PNG or JPEG is shrunk by the scale (default 4) to the game's size and compared with every room's background at every place it fits, by the correlation of their brightness in 8-pixel cells, then lined up to the pixel. Lists each image's room, score (1 is a match) and runner-up, and the place of one smaller than its room (half of a wide room). An image under 0.95, or one that repeats a better image of its room, is matched against object images: its room's objects at their places that it shows better than the background there (a room with an object's state drawn in), and the object frame in any room it best matches (a full-screen object such as the credits pages, the inventory's backdrop). `--out MOD` makes `MOD` a hi-res mod (sets `"scale"` in its `mod.json`, see [Mods](#mods)) and writes each room's images at their places and the scale to `MOD/rooms/<room>/background.png`, an image that is a whole object's to `MOD/rooms/<room>/objects/<frame>.png` (named as the export names it), and the rest to `MOD/_unplaced` |
| `match TRACK [FILE] [--in DIR] [--chunks]`, `match all --out FILE [--in DIR] [--only T,T…]` | Where a game music track (number or name) is in a FLAC, for a music mod: the track cut into 4 s chunks, each found by normalised cross-correlation (FFT at an eighth of the game's rate, then to a fraction of a sample at its rate), the runs of chunks at one offset, the game's jumps carried into the file's time, and the `mod.json` entry they give (`start`, `end`, `loopStart`, `loopEnd`, `fadeMs`). Without FILE every FLAC under the mods folder (or DIR) is scored by a few chunks, the best five listed (marking the one `mod.json` already maps), and the best matched in full. `--chunks` lists every chunk with its score and the next best place's. Each match is made plainly and whitened (differenced, for another mix or master of the recording) and the higher score kept. `all` does it for every music track in the bundles, a line per track as it goes, and writes the `mod.json` to FILE: each entry with its `score` (the share of the track found, by how well), `mode` and `notes`, a blank `file` (with `best`, the nearest guess) for a track not found, and `previously` where FILE had mapped it elsewhere; FILE's cutscene keys and other fields are kept, and FLACs are looked for beside it and under it unless `--in`; a `file` is a path from the mod's `music/` or its folder, or a name found under `music/`. `--only 1100,Treasure` matches just those tracks and keeps FILE's other entries |

| `boot [--seconds N] [--save FILE@S …] [--load FILE] [--saves DIR] [--replay [FILE]] [--click WHAT@S …] [--right-click WHAT@S …] [--key KEY@S …] [--calls] [--every-frame] [--vars V,V…] [--boot N] [--png FILE] [--limbs A,A…]` | Runs the game's scripts headless with MMUCS.Runtime's interpreter: the engine's start-up variables, the boot script (global 1), then N seconds of frames (default 10; COMI gets a frame every 5 jiffies, 12 a second). Prints each script starting (`▸`) and ending (`◂`, with why: ended, stopped, room left, fault), indented by nesting, with the time and frame; rooms entered with their size; the lines said and printed (`SAY actor N TAG: text`, with the speech read along so a line lasts as long as it's spoken; `SYSTEM` for system messages, which wait for a key as in the game: the next `--key` given answers it), the sound effects (`SOUND N starts`; read along with the game's time so the scripts see them end, not heard) and the music (`MUSIC`: each state and sequence the scripts set, the track and how it takes over, from the tables in comi.exe; followed but not heard, so a sequence lasts until the scripts end it); faults and warnings. Then the scripts still running (sleeping or running, and where), some variables (`--vars` adds more by number, name or `bitN`) and the instructions the interpreter doesn't carry out yet, with how often they were met. During frames each line is shown the first time and repeats are counted, unless `--every-frame`. `--calls` also lists those instructions as they're met, with their arguments and text. `--boot N` is the boot parameter (0; `--param` also works), ScummVM's `-b`: COMI's boot script jumps straight to a room, without the flags, inventory or music playing there would have set, so compare odd results with ScummVM booted the same way. `--click WHAT@S` presses the left button S seconds after boot (default 1) on WHAT: an object of the current room by number or name (at its middle), `actorN` (the middle of where actor N was last drawn) or `X,Y` on the screen, and lets go 6 jiffies later; `--right-click` likewise; `--hold WHAT@S` holds the left button for a second (the verb coin); `--move WHAT@S` moves the pointer there without a click; `--key KEY@S` presses a key (a character, `esc`, `enter`, `space`, `f1`…`f9` or a code). The current room's objects, their places, where an actor stands at each and which way it faces, and which are untouchable are listed at the end, then its actors (costume, place, facing, animation, box, scale, layer, where they were drawn, their limbs' AKSQ positions, special-draw, and the palette slots their costume draws in, through the actor's own colours when `remap-costume` or `actor N palette` set some). Then the palette: the room's palette in use and the slots the scripts changed, in runs with the `palette-intensity` r,g,b (of 255) that gives them from the room's colours, or `set` for colours set outright, and the shadow tables the scripts set (`build-palette-shadow`: what each multiplies the screen by, of 255). The verbs on the screen (dialogue choices: their numbers, where their text was drawn and the text) are listed too. `--png FILE` saves the room as the game window draws it at the end, in the colours on the screen: the objects the engine draws, the actors as its last frame drew them, and its texts (listed too, with their places). `--limbs A,A…` prints those actors' costume, place, box, scale, animation and limbs (AKSQ position, `s` if stopped) each time any of them changes, with the speech's lip sync (`mouth W×H in TAG`) while the actor talks. `SAVE` and `LOAD` show the scripts' temporary save being taken and put back (`room save-game` and `room load-game`: the F1 menu saves before it takes the screen over and loads on Return to Game); `QUIT` a script quitting (the menu's Quit), which ends the run. `--save FILE@S` writes a save file S seconds after boot, as the game window's F6 does (the engine, music, speech and effects), with how many objects went in, by type, and the engine's own services left to the reader; `--load FILE` loads one over the booted game before the frames start, as F4 does, listing anything the game no longer has. `--saves DIR` gives the F1 menu a saves folder, as the game window's per-game one: its slots (`SAVE slot N "name"` and `LOAD slot N` when the menu writes and loads them) and the registry settings the game keeps (`REGISTRY name = value` as it writes them, such as the menu's page). Without it the slots are empty and the registry gives its defaults. `--replay FILE` feeds in a recording from the game window (`--game … --record [FILE]`); with no FILE, the newest one `--record` wrote to its default folder (the app data's `recordings`): the pointer, the buttons, the keys, the answers to system messages, skipped videos and loaded saves, each at the jiffy it reached the window's engine (`PRESS` lines show where a button went down and on what). It takes the recording's boot parameter, and runs to where the recording ended, unless `--boot` or `--seconds` say otherwise; other options can be added (`--png`, `--vars`, `--limbs` …). The window's smooth camera can put the room under the pointer a few pixels off while the camera moves, so a replay can go its own way: the end lists any recorded answers no system message asked for. A run with `--load` ends as the saved run would have (compare their end states). Exits 1 if a script faulted |

`ROOM` is a room number (`14`) or name (`town`).

## Mods

A mod is a folder in `_mods` beside the game with a `mod.json`. It holds what it replaces where an export writes it, so an exported file can be edited and dropped in:

```
_mods/COMI_FLAC_Music/mod.json            "tracks": the game's music its audio stands in for
_mods/COMI_FLAC_Music/music/…/01 - ….flac  its audio, in any folder under music/
_mods/WideScreenMod/mod.json               { "enabled": true }
_mods/WideScreenMod/rooms/022_clring-a/objects/041_clring-a-haggis-caber_f0.png
_mods/WideScreenMod/rooms/022_clring-a/objects/041_clring-a-haggis-caber_f0.meta.json
_mods/WideScreenMod/rooms/022_clring-a/costumes/akos_02A4A050/cel_048.png
_mods/WideScreenMod/rooms/022_clring-a/costumes/akos_02A4A050/meta.json
_mods/UpscaledBackgrounds/mod.json         { "enabled": true, "scale": 4 }
_mods/UpscaledBackgrounds/rooms/014_fortbase/background.png
_mods/UpscaledBackgrounds/rooms/069_stancrpt/objects/048_stans-office_f0.png
```

`"enabled": false` turns a mod off. Mods are read in name order, and where two replace the same thing the first wins. The game window uses them, and so do the Room and Costume viewers while their **Mod images** toggle is on.

- **Music** (`MusicMods`): `mod.json`'s `tracks` maps the game's tracks (`"1100-Hold1"`) to files, with the stretch played and the loop. A file is found by its path under `music/`, or by its name in any folder there.
- **Object images** (`ObjectImageMods`): a PNG named as the export names the object's image is drawn in its place. It can be any size. It goes at the object's place unless the `.meta.json` beside it gives its top-left in the room: `{ "x": 232, "y": 392 }`. `"shadowTable": 7` there picks the shadow table its shadow pixels use.
- **Costume cels** (`CostumeCelMods`): a PNG named as the export names the cel is drawn in its place, in every frame that uses it. It can be any size. The costume folder's one `meta.json` gives each cel's top-left from the game cel's: `{ "cels": { "cel_048": { "x": -13, "y": 0 } } }`. A cel it doesn't list stays at the game cel's corner (0,0), which suits a repaint but not a cel extended up or left.

- **Hi-res mods** (`HiResMods`): a mod whose `mod.json` gives a `"scale"` over 1 has that many of its pixels to a game pixel, so a 4× mod's 640×480 room is 2560×1920. Its `rooms/<room>/background.png` is drawn over the whole room in place of the game's background, and its object images (named as the export names them; a `.meta.json`'s `x`/`y` place them, in game pixels) in place of the objects', both at their own resolution and in full colour. A blasted object (the credits' pages, the inventory's backdrop) is drawn from it too. When the scripts change the colours (fades, lights, `palette-intensity`), each pixel is tinted by how the colour of the game's index under it changed from the room's own (screen ÷ room, per channel, smoothed between game pixels), so the picture fades and lights with the room. The palette mods below leave a hi-res mod's images alone, and its costume cels aren't drawn yet. The game window, `mprobe boot --png` and the Room viewer (while its **Mod images** toggle is on, in the room's own colours) draw them; the Inspector's Position section moves only palette mods' images. `mprobe backgrounds` maps a set of unnamed upscaled backgrounds into one, and `mprobe boot --png` says whether the hi-res background is drawn as made or tinted.

The game draws in palette colours, so a palette mod's PNG is taken into them:

- **Object images:** each opaque pixel becomes the room palette's colour nearest it. A partly see-through pixel is baked over the room's background under it. A dark one at least a fifth opaque (the export's 40% black) is a shadow, drawn as the game draws a costume's: the background times shadow table 6, or the table the `.meta.json`'s `"shadowTable"` names, so it matches the costume it continues. In the game window that's the table as the scripts set it (`build-palette-shadow`); elsewhere COMI's usual values (table 6 is 189 of 255, table 7 is 219). Other partly see-through pixels are blended.
- **Costume cels:** each opaque pixel becomes the costume's nearest colour. A dark pixel at least a fifth opaque becomes the costume's shadow colour, so the game's shadow mode applies; the export draws shadows as 40% black. Fainter pixels are transparent.

`mods` lists each costume cel with its size against the game's, its offset and how much of the game's cel its PNG has there. Over 90% means it lines up; less means the offset is wrong or the cel was repainted. `--place` finds where the game's cel sits in each PNG that doesn't line up (no offset, or extended since) and saves those offsets to `meta.json`, keeping the rest of the file. A cel it can't match to 90% keeps its offset, and the best fit is printed. To do only some cels, name them; named cels are worked out again even when they line up, and get their best fit when it's at least 50%:

```bash
mprobe mods --place                       # every cel that doesn't line up
mprobe mods --place cel_044               # one cel, by its file
mprobe mods --place 44,47                 # by number
mprobe mods --place akos_02A4A050/cel_044 # by the end of its path, where two costumes have a cel_044
```

The Inspector's **Position** section in MMUCS shows the same offsets and places. It can move a mod's and save it to the same files.

## Checking the interpreter

```bash
mprobe boot                      # COMI boots into room 87, the difficulty choice, and waits for a click
mprobe boot --calls --seconds 0  # everything boot asks for that isn't carried out yet
mprobe boot --seconds 20 --click easyhard-hard-button-object@2
mprobe boot --seconds 60 --click easyhard-hard-button-object@5 --png cannon.png  # the first scene, its actors as the scripts put them
mprobe boot --seconds 70 --click easyhard-hard-button-object@5 --save cannon.sav@60  # then: mprobe boot --seconds 10 --load cannon.sav
                                 # pick Mega-Monkey: about 3.5 s later the game leaves for room 2 (thx)
```

## Refreshing the export for mscripts and mroom

```bash
dotnet run --project tools/mprobe -c Release -- export D:/exports/comi
python tools/mscripts/mscripts.py use D:/exports/comi
```

The export uses the variable names built into MMUCS.Core, so run it again after changing `src/MMUCS.Core/Names/variables.json` to see new names in the exported scripts. mscripts and mroom rebuild their indexes when the export changes.

## Notes

mprobe isn't part of `MMUCS.sln`, so building the app doesn't build it. It references `src/MMUCS.Core` directly and always runs the current code.
